# 🐔 Farm Records App (EBGF-Mobile)

A Flutter mobile app for monitoring and uploading farm records — scan tags with the camera, capture on-device OCR text, save structured records, and manage everything through a role-based admin system, all backed by Firebase.

---

## ✨ Features

### Core (all users)
- **Sign up / Log in** with Firebase Authentication (email + password).
- **Scan Tag / Add Record** — live camera preview with on-device OCR (Google ML Kit Text Recognition). No photos are ever saved to disk; recognized text is captured live, like a caption.
- **Configurable extra fields** — every record has a tag number plus a set of admin-defined fields (e.g. "Leg Band Color", "Bloodline", "Marks"). The number and names of these fields can change at any time without a code change or app rebuild.
- **Confirmation before save** — users review the tag number and all field values before a record is written.
- **View Records** — real-time list of all records (Firestore-backed, updates live across devices), with the ability to edit any record.
- **Export to Excel** — generate an `.xlsx` file of all records (columns match the current field configuration) and share it via the native share sheet.

### Admin-only
- **Admin Dashboard** — central hub for admin tools.
- **User Management** — promote/demote users between `Farm User` and `Admin`, with a confirmation dialog before every change. Updates live for all admins.
- **Tags Editor** — rename, add, or remove the extra fields shown on every record. Changes apply app-wide immediately (Scan screen, Records screen, Excel export).
- **Analytics** — total records, total users, records added today, a breakdown of records per user, and a live feed of recent activity.
- **Audit Log** — a running, color-coded, icon-coded history of every significant action (logins, record create/edit/delete, promote/demote, field-label changes).
- **Delete records** (regular users can edit but not delete).

## 🔥 Firebase Setup

This project is already wired to a Firebase project (`ebgf-records`) via `lib/firebase_options.dart`, `firebase.json`, and `android/app/google-services.json`. To point it at your **own** Firebase project instead:

1. Install the [Firebase CLI](https://firebase.google.com/docs/cli) and the [FlutterFire CLI](https://firebase.google.com/docs/flutter/setup):
   ```bash
   dart pub global activate flutterfire_cli
   ```
2. Create a Firebase project in the [Firebase Console](https://console.firebase.google.com/) with **Authentication** (Email/Password provider) and **Cloud Firestore** enabled.
3. Run:
   ```bash
   flutterfire configure
   ```
   This regenerates `lib/firebase_options.dart` and `android/app/google-services.json` for your project.
4. Deploy the Firestore composite index used by the audit log:
   ```bash
   firebase deploy --only firestore:indexes
   ```
   (defined in `firestore.indexes.json`)

### Firestore collections

| Collection | Written by | Purpose |
|---|---|---|
| `users` | `auth_service.dart` on sign-up | Profile doc per account: `name`, `email`, `role` (`admin`/`user`), `createdAt`. Document ID = Firebase Auth UID. |
| `records` | `records_service.dart` | One doc per farm record: `tagNumber`, `fieldValues` (list), `createdBy`, `createdAt`. |
| `audit_logs` | `audit_log_service.dart` | One doc per tracked action: `action`, `performedBy`, `description`, `timestamp`, `expireAt` (30-day TTL). |

> **Roles:** every new sign-up is created with `role: "user"`. Nobody can self-promote — an existing admin must promote them via **Admin Dashboard → User Management**.

## 🚀 Getting Started

### Prerequisites
- [Flutter SDK](https://docs.flutter.dev/get-started/install) `>=3.38.4`
- Android Studio / Xcode (for platform toolchains) or a physical/emulated Android device
- A Firebase project (see above)

### Install & run

```bash
# 1. Install dependencies
flutter pub get

# 2. Connect a device or start an emulator, then run
flutter run
```

### Required permissions
The app needs **camera** access to scan tags. On Android this is requested at runtime the first time the Scan screen opens — make sure you grant it, or the camera preview won't initialize.

### Build a release APK
```bash
flutter build apk --release
```

## 📖 How the "configurable fields" system works

Originally the app had 3 hardcoded fields (`Field 1`, `Field 2`, `Field 3`). Now:

1. `FieldConfigService` (a singleton `ChangeNotifier`) holds the current list of field labels, defaulting to `['Leg Band Color', 'Bloodline', 'Marks']`.
2. An admin edits these in **Tags Editor** — labels can be renamed, added, or removed (at least one field is always kept).
3. Every screen that shows or edits a record — `ScanScreen`, `RecordsScreen`, and the Excel exporter — reads the current labels from `FieldConfigService.instance.fieldLabels` at build time, so the number of inputs/columns always matches what's configured.
4. `FarmRecord` only stores raw `fieldValues` (a `List<String>`), not the labels themselves — so renaming a field later doesn't require touching old records; the label for `fieldValues[i]` always comes from the current config.
